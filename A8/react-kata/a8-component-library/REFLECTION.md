Reflection on Accessibility

The decision I am most proud of is how I handled error states on the Form Fields. Previously, I would just style text red and hope the user saw it. Now, I've linked the error message to the input using aria-describedby and aria-invalid="true". When a screen reader focuses the input, it announces "invalid entry" and reads the exact error message. It also uses role="alert", so if the error appears dynamically while typing, the screen reader interrupts to announce it. This makes the forms genuinely usable for blind users, not just visually clear.

The decision I found genuinely tricky was the focus trap in the Modal. It is easy to move focus into the modal on open and return it on close. However, preventing the Tab key from escaping the modal into the browser chrome or the page behind it requires careful event interception. I had to write logic to get all focusable elements, intercept the Tab and Shift+Tab keydown events, and manually cycle focus from the last element to the first (and vice versa). I also had to ensure that if the modal had no focusable children, it didn't crash, and that pressing Escape immediately closed the modal and returned focus to the trigger button.
